# 01. Commit

Rules for every commit in 9router.

## Language

**All commit messages are written in English**: subject, body and footer, including commits made by AI agents.
Code identifiers, paths and quoted UI copy keep their original form.

## Format

[Conventional Commits](https://www.conventionalcommits.org/):

```text
<type>(<scope>): <subject>

<body>

<footer>
```

The scope is optional. Body and footer are optional but recommended for anything non-trivial.

### Type

| Type       | Use for                                                    |
| ---------- | ---------------------------------------------------------- |
| `feat`     | A new user-facing capability                               |
| `fix`      | A bug fix                                                  |
| `refactor` | A code change that neither adds a feature nor fixes a bug  |
| `perf`     | A performance improvement                                  |
| `style`    | Visual or formatting changes that do not alter behavior    |
| `docs`     | Documentation only                                         |
| `test`     | Adding or correcting tests                                 |
| `build`    | Build system or dependency changes                         |
| `ci`       | CI configuration                                           |
| `chore`    | Maintenance that does not touch app behavior               |
| `revert`   | Reverts a previous commit                                  |

### Scope

The area that changed, lowercase: `api`, `dashboard`, `db`, `providers`, `translator`, `executors`,
`handlers`, `routing`, `oauth`, `ci`. Leave it out when a change spans many areas.

### Subject

- Imperative mood: "add", "fix", "remove".
- Starts lowercase unless the first word is a proper noun or acronym. No trailing period.
- 72 characters or fewer, type and scope included.
- Describe the outcome: `fix(auth): reject unsafe next_path redirects`, not `fix: update widget`.

### Body and footer

- One blank line after the subject. Explain why the change was needed. Wrap at about 72 characters.
- Reference issues: `Refs: #6`. Breaking changes: `BREAKING CHANGE: <what breaks and how to migrate>` or
  `feat(api)!: ...`.

## Co-authors

**Never add an AI tool as a co-author** (`Co-authored-by: Claude ...`, `Co-authored-by: Gemini ...`). Commits
with an AI co-author line are rejected by the `commit-msg` hook. Disclosing AI use (and the model) in the PR
description is fine.

## Examples

```text
feat(routing): add combo first-response grace

A stalled combo member blocked the whole request until timeout. It is
now skipped after the grace window and rejoins on the next request.

Refs: #12
```

Not allowed:

```text
update stuff                      # no type
fix: perbaiki login               # not English
feat(web): Added login page.      # past tense, capitalized, period
```

## Scope of a commit

- One commit per coherent change. Stage files explicitly and review `git diff --cached` first.
- Never commit `.env` files, credentials, `storage/`, `target/` or `web/build/`.

## Enforcement

Install the hooks once per clone:

```bash
git config core.hooksPath .githooks
```

`commit-msg` (`scripts/check-commit-msg.sh`) rejects a subject that does not match
`<type>(<scope>): <subject>`, starts uppercase, ends with a period or exceeds 72 characters, a body that does
not start after a blank line, and any AI co-author line. Git-generated merge and revert subjects are skipped.
The English-only rule is checked in review.
